# After plan 1 — measured results

Companion to the pre-upgrade baseline. Everything below was measured locally
against `next start` on a fresh production build, with the measurement harness
that owns its own server (`scripts/measure-bundle.mjs`, `scripts/measure-cls.mjs`
— see `scripts/port.mjs` for why that matters).

**Lighthouse numbers are not here.** They belong against a Netlify deploy
preview, and this branch has not been pushed. See "Still outstanding".

## First-load JavaScript, gzipped

| Point in the plan                              | `/ar`        | `/en`            |
| ---------------------------------------------- | ------------ | ---------------- |
| Next 14 baseline (live site, 2026-07-27)       | ~183 KB      | — (single route) |
| After the Next 16 / React 19 upgrade           | 252.8 KB     | 252.8 KB         |
| After task 8 (server components + islands)     | 247.3 KB     | 247.3 KB         |
| After task 10a (LazyMotion + `motion/react-m`) | 238.7 KB     | 238.7 KB         |
| After task 10b (CSS reveals)                   | 235.6 KB     | 235.6 KB         |
| **After plan 1**                               | **236.1 KB** | **236.1 KB**     |

**The 150 KB target was not met, and the honest figure is 236.1 KB** — 53 KB
_above_ the Next 14 baseline the plan started from. The upgrade itself cost
~70 KB (React 19 plus the Next 16 runtime); every task since has been clawing
that back. Two owner decisions bound how far this could go:

1. The remaining animated islands keep `motion`. Removing it would buy roughly
   40 KB and cost the site its feel.
2. The final target is set in plan 3, after the new hero lands and changes the
   calculation.

The last 0.5 KB is task 14's drawer focus trap and language-menu keyboard
handling. Both are accessibility fixes; neither is worth reversing for the
number.

## Fonts, per locale

| Route | Before             | After                                   | Preloaded |
| ----- | ------------------ | --------------------------------------- | --------- |
| `/ar` | 111.0 KB (5 faces) | **55.6 KB** (6 faces, Tajawal only)     | 0         |
| `/en` | 111.0 KB (5 faces) | **84.9 KB** (2 faces, Playfair + Inter) | 0         |
| `/fr` | 111.0 KB (5 faces) | **84.9 KB** (2 faces, Playfair + Inter) | 0         |

Arabic legitimately fetches more _files_ than latin — Google splits Tajawal into
3 weights × 2 unicode ranges — while downloading far fewer bytes. Counting files
was the wrong gate; the tests assert that the two locales' font sets are
disjoint, plus the computed `font-family` per locale.

## Test suite

66 passing, 6 skipped. The 6 skips are the deploy-only header assertions, which
`next start` cannot serve; run them with
`PLAYWRIGHT_BASE_URL=https://<preview>.netlify.app npm run test:e2e`.

Two tests are marked PROTECTED in `tests/smoke.spec.ts` and must not be
weakened: computed `font-family` per locale, and computed `opacity > 0` on at
least one reveal per section. Each exists because a real regression passed a
weaker check.

## Still outstanding after plan 1

Not started, and not in this plan's scope:

- **The admin panel** (spec §3.5–3.7) — auth, Netlify Blobs content store,
  server actions, image uploads. Plan 2.
- **SEO**: OG images per locale, JSON-LD, `sitemap.ts`, `robots.ts`, Search
  Console verification, and the marketing-copy rewrite. This is the remaining
  half of B13.
- **The Prism Stack hero** (spec §3.8). Plan 3.
- **The contact rework** (spec §3.9): removing the email address everywhere and
  recomposing the section around form / WhatsApp / social links.
- **Axe accessibility checks** in the Playwright suite.

Verified locally but **not on a deploy**:

- The security and cache headers in `netlify.toml`. Netlify applies them; `next
start` does not.
- Lighthouse mobile scores for `MIGRATION.md`.
- That Netlify Forms still works on Next 16 — the empirical check the owner
  asked for.

Known and deliberate:

- `script-src 'unsafe-inline'` in the CSP. A nonce forfeits static prerendering;
  hashing does not scale to the 21 RSC flight scripts Next emits per route. Three
  ways out are recorded in `PROGRESS.md`.
- `npm audit` reports 12 high-severity advisories, all `sharp`/libvips reached
  through `next`'s own bundled copy. `npm audit fix --force` proposes
  `next@9.3.3`, so it is not a fix.
